# 최신 룰셋 미지원 카드 4장

2026-11-07, 기물 카드 18장·오프닝 카드 24장·중반 50장·후반 32장 이식 완료 기준.
대상은 `augment_chess_20261017`의 최신 실행 프로필이다.
275장 중 지원 271장을 제외한 **4장 전부**를 정리했다. 이 중 **0장은 활성 이식 대상**이고,
**4장은 원본 비활성 기록**이다. 비활성 4장은 실행 지원 목표에 포함하지 않는다.
이 4장 말고 남은 이식 대상은 없다.

이 룰셋은 2026-10-17 발표를 기준으로 2026-10-28 live 번들을 수집한 것이다.
10-17 당시 바이트를 검증했다는 뜻은 아니다. 카드 설명은 보관된 canonical 카탈로그에서 가져왔다.

## 목록의 근거와 읽는 법

- [최신 카탈로그](../rulesets/augment_chess_20261017/cards/catalog.json): 이름·분류·효과 설명·활성화·턴 정책.
- [최신 실행 프로필](../rulesets/augment_chess_20261017/cards/implemented.json): `pending` 40개의 ID와 미지원 사유.
- [0915 대비 차이](../rulesets/augment_chess_20261017/sources/0915-delta.json): 변경 필드와 이전/이후 정의.
- [원본 수집 근거](../rulesets/augment_chess_20261017/sources/source-manifest.json): 번들 URL·digest·수집 시각.
- [카드 구현 안내](card-implementation.md): 카드 파일·등록부·공통 처리·과거 정의와 테스트 위치.

`변경`은 `changed_contract_not_ported`, `신규`는 `new_card_not_ported`,
`원본 비활성`은 `disabled_upstream`에 대응한다. 변경 카드 34장 중 33장은 설명 변경이 기록돼 있다.
변경 필드 표시는 자동 비교 기록이며 실제 동작 차이의 전수 조사 결과는 아니다.
마지막 열의 확인사항은 설명과 현재 엔진 구조에 근거한 **구현 전 검토 항목**이다.
특히 신규 기물의 행마·능력, 대상의 세부 제약과 설명의 “수/턴” 단위는 원본 실행 코드로 확정해야 한다.

RULE은 canonical 데이터의 `activation` 값과 별개로 엔진에서 규칙 설치로 처리한다.
패시브의 발동 시점은 획득 즉시·잠금 해제·턴 경계 등 카드별 계약으로 확인한다.
같은 이름도 ID가 다르면 별도 카드다. 예: RULE 실수와 중반 실수, 두 종류의 컨베이어.

## 이식할 때의 공통 작업

1. 원본의 대상 선택·실행 함수와 이전 구현을 비교한다. 이름·설명만으로 과거 handler를 허용하지 않는다.
2. 획득 조건, 설치/사용 시점, 소유자, 예약의 단위, RNG 호출 순서와 실패 시 처리를 확정한다.
3. `card_ids.rs`의 기존 상수를 확인한다. 새 ID가 없을 때만 추가하고,
   `engine/cards/<id를_밑줄로_변환>.rs`와 등록부에 구현을 연결한다.
4. 예약·지속·새 기물 상태는 반복 키와 탐색 분기·복원까지 반영한다.
5. 웹의 대상 선택·선택지·상태 표시와 탐색의 합법 행동 열거를 연결한다.
6. 원본 전이 fixture와 경계·색상·난수·실패 원자성 테스트를 추가한 뒤 지원 프로필을 갱신한다.
   아래 목록과 수량도 같은 변경에서 갱신한다.

기물 카드 18장의 획득 조건·변환·희생·배치와 전용 동작은 [기물 카드 이식 기록](piece-card-ports.md)에 정리했다.
현재 PIECE와 활성 OPENING 분류에는 미지원 카드가 없다. 오프닝 작업의 세부 범위는 [오프닝 카드 이식 기록](opening-card-ports.md)에 있다.
메타 카드인 검은 상자·랜덤룰렛·규칙 티켓은 호출 대상 카드/기물/RULE의 최신 후보 풀과
미지원 항목의 처리를 함께 설계해야 한다.

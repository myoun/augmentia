# 탐색 교사 전환 후 구조

2026-10-29 기준. 목표는 학습 없이 강한 탐색 교사를 구축한 뒤 그 결정을 학습하는 것이다.

## 실행 경로

`augment-core`는 규칙과 상태 전이를 소유한다. `augment-search`는 코어의 합법 행동 배치를
받아 탐색한다. `augment-app`은 세 실행 파일을 제공한다. `web`은 분석·편집·분기 기보,
`play`는 수동 대국, `snapshot`은 원본 카드 추출과 규칙 비교를 담당한다.

현재 workspace는 `core`·`search`·`app` 세 crate로 구성한다. 모델 실행·학습·승격·ONNX와 V3/V4 데이터 계약,
별도 MCTS V5 실험은 제거했다. 루트 빌드나 실행에 Python·모델·GPU는 필요 없다.

앱 진입점은 `augment-app/src/bin/{web,play,snapshot}.rs`이며 각 모듈의 `run`만 호출한다.
웹의 HTTP·세션·설정·view·정적 파일은 `src/web/`, 수집기는 `src/snapshot/`에 모은다.
규칙과 탐색을 앱 안으로 복제하거나 실행 파일끼리 서로 호출하지 않는다.

최신 카드 235장의 획득 조건·효과·행동 열거는 `augment-core/src/engine/cards/<card_id>.rs`와
단일 등록부에 모은다. 과거 룰셋 분기는 `engine/compat/`에 분리한다.
공통 정의 타입은 `card.rs`, Rust ID는 `card_ids.rs`, 과거 메타데이터는
`compat/card_definitions.rs`가 소유한다. 최신 정의는 자체 카탈로그와 실행 프로필에서 구성한다.
공통 기물·턴·보드 처리와 카드별 처리의 경계는 [카드 구현 안내](card-implementation.md)를 따른다.

## 규칙과 탐색의 interface

- 규칙: 불변 `ruleset_id`·manifest·원본 provenance.
- 실행: 실제 상태·합법 행동·이벤트·확률 결과·종료 판정을 코어가 소유한다.
- `LegalActionBatch`: 엔진과 원본 상태에 묶인 열거 행동 목록이다. 다른 상태에 재사용하지 않는다.
  열거 밖의 동적 목표는 일반 checked apply를 사용해야 한다.
- 전략 탐색: `search` / `search_with_cancel`의 작은 interface 뒤에 반복 심화·행동자 기준
  max/min·턴 깊이·확률 표본·예산 처리를 둔다.
- 전술 진단: `tactics::find_tactical_win`은 원래 AND-OR 알고리즘을 직접 엔진 행동으로 실행한다.
  반환 `Action`은 별도 모델 인덱스 없이 다시 적용할 수 있다.

일반 탐색의 깊이는 완료된 플레이어 턴 수다. 전술 진단은 기존 알고리즘의 액션 깊이를
명시적으로 유지한다. 같은 행동자 연속 행동은 AND-OR의 같은 쪽 선택으로 처리한다.

## 결과의 의미

전술 결과는 열거된 결정론적 full-state 트리 안에서만 해석한다. 알려진 카드 대상 누락,
확률 전이와 예산 중단은 미확인으로 처리한다. 깊이 안에서 승리를 찾지 못했다는 사실은
패배나 안전함을 뜻하지 않는다. 이 진단을 비공개 상태에 기반한 플레이어 정책으로 연결하지 않는다.

일반 탐색의 표본 평균과 휴리스틱은 승리 증명·실측 승률·Value 정답이 아니다.
루트 열거가 전체 적용 가능한 행동을 포함한다는 보장도 아직 없다.

## 교사 데이터를 만들기 전

1. 동적 카드 목표와 열거 coverage를 해결하고 원본 전이 대조를 늘린다.
2. 관측 가능한 정보와 진단용 실제 상태를 구분한다. [관측 원칙](observation-safety.md)을 따른다.
3. 전술 검사·왕 안전·카드 가치·별 종료 평가를 개선한다.
4. 같은 시간 예산·paired seed·색상 교환으로 탐색 교사의 기력을 검증한다.
5. 그 뒤 실제 사용한 정보·행동·탐색 예산·coverage·종료 출처를 기록하는 작은 데이터 계약을 만든다.

현재 코드 정리는 새 교사의 완성이나 기력 우위 판정이 아니다.
